## 入门2 特征与embeding 业务字段怎么变成模型输入
特征处理
	模型能用到哪些信息（哪些保留、哪些丢失）、模型怎么泛化（一个取值学到的经验能不能被相似取值复用）、训练与线上是否一致（离线喂进去的和线上算的是不是同一种表达）

特征协议:三元组
```
struct FeatureInfo {
　int slotId;　　　　　　　// 特征属于哪个字段或特征组
　int64_t featureSign;　　 // 具体取值的查表 key，离散特征主要信息
　float value;　　　　　　 // 数值或权重
};
```
连续特征也是这个协议，featuresign固定为1，但信息全在value里

featureSign约束:当成不透明的64位key,不可计算
	slotid放高32位，具体取值的编号放低32位

生日悖论，一个slot内有7.7万不同取值时，出现至少一次冲突的概率超过50%
性别，10^0，不存在;城市，10^3，可忽略;广告ID，10^6，少量冲突;GUID，10^8，不可避免大量冲突。
	取值冲突后会共享同一条embedding，模型无法再区分它们

工业界仍采用特征哈希: 冲突换来无状态、可扩展的特征生成

### 最重要一点:sign是查embed表的key，不是embedding
sign不能直接当标量喂给模型
	1 虚假的顺序关系，sign大不代表后一个类别更大
	2 虚假的距离关系，哈希值接近不代表类别相似
	3 无法学习，sign是始终固定的，但是embedding向量是可以训练的
	4 数值精度 64位sign转成float32后，超过一千六百万的相邻整数无法区分


embedding层数学形式    $E∈R^^(N×d)$
	N是slot取值总数(业务分布决定),d是取值向量维度(由模型决定，按基数量级配置)
	工程上不必构建onehot，直接拿featuresign去查那行就可以
	e.g.如果看篮球内容的用户经常点运动鞋广告，训练会让这两个类别的向量逐渐靠近
		当查表取出了这两个向量，模型计算相似度并预测点击率；若真点击了，则反向传播更新这一行
	d广告ID 10^6量级，通常在8-32维权衡

模型看到的从来不是一个 slot，而是全部 slot 的组合
	共享反而带来泛化

### 三条编码路径:离散五步，dense四步；分桶
离散: 规范原始值->选slot->生成sign->设置权重(单值类别value=1.0)->查embedding，用sign选出参数表一行，输出`1.0xE[sign]`
	多值离散特征: 兴趣标签`[篮球，跑步，摄影]` 是一个slot产生三条sign

dense: 校验兜底(NaN)->变换与归一化(直接 log1p min-max z-score)->固定sign(统一featuresign = 1)->把变换后的数值放进vlaue
      $dense_vector=x×W，其中W=E_slot[1]$
      
x 是归一化后的数值，W 是该 Dense slot 那条固定 Embedding，由训练学出。这个结构在数学上等价于一个无偏置的一维线性层投影到 d 维：数值本身不选行，**只是把同一组投影权重放大或缩小相应的倍数**。
	注意 Dense slot 里的 W 有时也被口头叫做 Embedding，但角色和离散 Embedding 不同：离散是「每个类别一行」，Dense 是**整个 slot 只有一行**，本质是一组可学习的投影权重。


分桶是第三种形式;先把连续值切成区间，再把桶编号当类别处理(每个桶有独立的embedding)
	**非单调的区间效应**  dense是x乘W，x越大结果就越线性大
	四种分桶:等宽(长尾问题)等频(最常用)对数(数字跨度大)顶桶截断(防止极端造新桶)

分桶和 Dense 经常同时用：分桶负责区间效应，Dense 负责连续大小
	代价是**离线必须用完全相同的桶宽、顶桶、log1p 和异常兜底**。

### embedding表的边界:内存 准入与一致性
embd是参数表，内存需要先估算
	$内存=Σ slot(|V slot|×d slot×4字节)$
	|V_slot| 是该 slot 的唯一 featureSign 数，由线上取值分布统计得到；d_slot 是该 slot 的维度，由模型配置决定;四字节是float32存储精度，还有adam等隐性开销

表的大小取决于唯一取值数(featureSign)
表不能无限膨胀
	准入:取值数达到阈值才建表项
		根本事实:embed与上层网络联合训练，前向查向量、拼接池化、DNN 出分，反向同时更新embed和网络参数，只有被训练样本覆盖到的key才有效更新;->长尾出现次数少，向量接近随即初始值
	淘汰:若干天未出现则删除(清理失活用户和下线广告) ->内存清理
	OOV:out-of-vocabulary 查不到的key返回零向量默认桶/延迟建表->新key兜底
	
表征质量: 腾讯kdd24观察到工业embed训练后期出现维度坍塌，大量参数向量压进一个低维子空间；解决是扩成多条embed向量

离线在线一致性
	必须严格对齐的项目:哈希算法 种子 字符串编码 slotid枚举值 分桶 归一化统计量 缺省规则 字符串trim 拼接顺序与分隔符（不报错)
	处置原则:将变更变成模型变更
工程上有两个做法：优先让离线与在线共用同一份特征库或特征库配置；上线前抽取真实请求，逐字段对比两侧生成的三元组，sign、value 逐条 diff，不一致的字段在发布前就能发现。

### 结论
这套体系运转得很好，但收回到生成式主线看，它有一个明显的局限：离散表示里，每个类别的向量完全靠行为数据学出来。一条新广告、一个冷启动用户，没有行为记录就没有有效向量，频次准入直接把它挡在表外；低频取值即使入了表，向量也接近随机初始化。Embedding **只能从共现数据学到类别之间的相关性，学不到内容本身的属性**。

生成式路线对这个问题的回答是**语义 ID**：让物品 ID 本身携带层次化语义。
